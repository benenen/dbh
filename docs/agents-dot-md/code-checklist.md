# 代码清单
> 写完代码逐条检查的 CLI、数据库与 Go 实现要求。

## CLI 与数据安全

- 完整命令和别名调用同一实现；保留已有参数语义和非零错误退出码。
- 批量 CSV/NDJSON 输出保持可供脚本消费；终端提示和错误不得混入结果数据。
- 连接名继续校验，路径不能逃逸配置目录；Unix 配置与历史权限保持目录 `0700`、文件 `0600`。
- 配置更新继续使用文件锁与原子替换；删除连接只删除配置，不删除数据库。
- 真实 DSN、密码、SQL 敏感值和个人配置不进入代码、测试夹具或提交。

## SQL 与补全

- 会话内查询、事务和结构读取使用同一连接；网络与数据库操作传递 context，并设置与释放超时。
- 在字符串、注释和 dollar quote 中出现的分号不切分语句；修改分句器时保留回归用例。
- `rows.Err()`、扫描错误和结果写入错误得到处理；资源释放不覆盖主错误，写操作的关闭错误需要检查。
- 补全在输入过程中显示候选，不自动改变已输入的 SQL；选择候选才修改缓冲区。
- 历史保存完整 SQL，保留字面量内的换行；`--no-history` 的禁用行为保持一致。
- 驱动特有的元数据 SQL 使用相应方言；验证状态分别说明 SQLite、PostgreSQL、MySQL，不能把跳过的测试算作通过。

## Go 与验证

- 有意义的 error 向上传递或就地处理；包装错误用 `%w`。终端提示和尽力清理的错误可显式丢弃，业务数据读写错误不可丢弃。
- 新建 context 后及时调用 cancel；新增 goroutine 具有退出路径，共享状态有同步机制。
- 修改的 Go 代码经过 gofmt，运行技术栈文档中的适用测试、编译与静态检查。
- 清理本次替换产生的旧依赖、旧帮助文本和未使用代码；不新增平行配置或第二套数据库访问层。
